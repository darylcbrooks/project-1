### [Project 47 - Investigating Rogue Processes w/ Splunk](https://youtu.be/urwj3x5SaxY)

Scenario: An alert has been generated by our Splunk SIEM indicating that a rogue process (explorer.exe) on our enterprise network may be enumerating a local user group.

In this project, I’ll be using the Splunk tool to conduct some threat hunting for a suspected rogue process within the enterprise environment.

## Accessing Splunk

Splunk is a Security Information and Event Management (SIEM) solution used for searching, monitoring, and analyzing machine‑generated data, primarily for IT operations, security, and observability.

![Image](https://github.com/darylcbrooks/project-1/blob/project-47/Project%2047%20-%20Step%2001.png)

I open my web browser and navigate to http://192.168.1.8:8000, where my installed instance of Splunk is hosted.

![Image](https://github.com/darylcbrooks/project-1/blob/project-47/Project%2047%20-%20Step%2002.png)

Next, I click on the Apps menu at the top of the page and choose the “Search & Reporting” option.

![Image](https://github.com/darylcbrooks/project-1/blob/project-47/Project%2047%20-%20Step%2003.png)

Once the page loads, I adjust the time parameters to remove the default time boundaries by changing the setting from “Last 24 hours” to “All Time.”

## Querying Security Log for Account Information

![Image](https://github.com/darylcbrooks/project-1/blob/project-47/Project%2047%20-%20Step%2004.png)

I apply the following query in the search bar to analyze Windows logs:
source=”WinEventLog:Security”

![Image](https://github.com/darylcbrooks/project-1/blob/project-47/Project%2047%20-%20Step%2005.png)

Right away, we can see several security logs generated from the host DESKTOP-BT4131D.

![Image](https://github.com/darylcbrooks/project-1/blob/project-47/Project%2047%20-%20Step%2006.png)

With all the security logs loaded, I navigate to the Process_Name field on the left side of the window. We can see explorer.exe listed with 37 log entries. Besides the browser update at the bottom, it appears to be the only process not executed from the System32 directory. I click on the explorer.exe entry for further investigation.

![Image](https://github.com/darylcbrooks/project-1/blob/project-47/Project%2047%20-%20Step%2007.png)

A new set of fields appears, all associated with the explorer.exe process. I click the Account_Name field on the left, and we can see that only one account is associated with executing this process: the “LabUser” account. Malware often disguises itself as explorer.exe to evade detection, blend in with legitimate system processes, and maintain persistence.

## Viewing Events Associated with the Malware

![Image](https://github.com/darylcbrooks/project-1/blob/project-47/Project%2047%20-%20Step%2008.png)

To view all related events associated with the suspicious explorer.exe process, I click the EventCode field and see a single event ID present: 4798. I select this event ID to view all logs containing it.

![Image](https://github.com/darylcbrooks/project-1/blob/project-47/Project%2047%20-%20Step%2009.png)

I click the small caret in the upper-left corner of the first log entry to expand it for more details. After scrolling down to the “Message” line, I can see a clear statement about the local group enumeration, including the account used, the domain, and the associated process. Attackers often enumerate local group memberships to identify privileged accounts they can exploit.

## Conclusion

By monitoring unusual activity linked to the “LabUser” account, I was able to improve my ability to detect and respond to a security threat before it escalated.
