### [Project 14 - Threat Hunting w/ Wireshark and sguil ](https://youtu.be/3S62CpAOZDM)

This project focuses on demonstrating how to monitor network traffic for potential threats. The two tools I will be using are Wireshark and Sguil. We’ll take a look at how to navigate their interfaces to find potential anomalous traffic within a network.

## How To Identify Threats w/ Wireshark

During a previous project of mine (https://github.com/darylcbrooks/project-1/blob/project-8/README.md), I discussed and demonstrated how Wireshark can be used to view data packet contents traveling in and out of a network. Now, I want to show how the tool can be used to identify potential threats within network traffic.

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2001.png)

Starting things off, I right‑click my Desktop and choose the “Open Terminal” option.

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2002.png)

Then I enter the following command to boot the Wireshark GUI on network interface ens32:

sudo wireshark -k -i ens32

Once the packet capture pane appears, I click the blue fin button in the upper-left corner of the window.

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2003.png)

Now that I’ve initiated Wireshark, I open another command terminal and change to the Lab 8 directory to have immediate access to the packet capture files that I’ll be using (cd Desktop/Lab\Files/lab8).

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2004.png)

Next, I open the pcap1 file to generate traffic on the network interface ens32 and provide my account password to gain elevated privileges (sudo tcpreplay -i ens32 -M10 pcap1). On the left side of the image above, we can see the data packets populating in the Wireshark GUI.

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2005.png)

In the terminal window, we can see that 24,240 packets have been generated from the pcap file, so now it’s time to stop the capture. To do so, I click the red stop button in Wireshark.

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2006.png)

Next, I click the Statistics menu at the top of the Wireshark window and choose the Endpoints menu item.

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2007.png)

A new menu appears, and I navigate to the IPv4 tab. As threat hunters, this is where we would go to identify the various endpoints that Wireshark discovered during a packet capture session.

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2013.png)

Any found suspicious IP address could then be provided to a tool such as VirusTotal (www.virustotal.com) to determine whether it’s known to be malicious.

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2008.png)

Going back to the Statistics menu, this time I choose the Conversations menu item.

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2009.png)

Similar to before, I navigate to the IPv4 tab of the menu that appears. This displays communication between IP addresses, and we can analyze this for any anomalous behavior. Notice the amount of traffic being generated by IP 10.1.25.119 to different addresses. This could be indicative of a command-and-control server sending beacons to compromised devices. Let’s further investigate 10.1.25.119 with the Sguil tool.

## Verifying Potential Threat w/ Sguil

Sguil is a GUI-based open-source network security monitoring and event-driven analysis tool. It differs from Wireshark by behaving more like an Intrusion Detection System (IDS) and alert aggregation console, rather than a deep packet inspector.

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2010.png)

To start up Sguil, I simply click on the highlighted Desktop icon.

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2011.png)

In the menu that immediately appears, I choose infosec-seconion-ens32 and click the Start SGUIL button to begin running the tool on my network interface.

![Image](https://github.com/darylcbrooks/project-1/blob/project-14/Project%2014%20-%20Step%2012.png)

Immediately upon entering the Sguil GUI, I’m greeted by five alerts — four of which concern our “friend” at 10.1.25.119. If we view the event message on the far right of the alerts, they all indicate that trojan malware has been detected (trojan malware = malware that masquerades as helpful or benign software). To investigate these alerts further, I click one of the alerts related to 10.1.25.119.

Initially, the bottom pane doesn’t show much information. However, once I check both the show packet data and show rule boxes, I can now view the contents of the troublesome packets. After scrolling through the data, I can see the trojan reference that Sguil is flagging.

## Conclusion

Now, of course, in reality, most malware-related packets aren’t going to have such obvious naming conventions as the trojan did in this project. What I wanted to highlight is how a IDS like Sguil can flag certain attributes in network traffic to alert analysts of potential anomalies. I also wanted to demonstrate how features of a packet-capturing tool like Wireshark can be used by analysts to detect network anomalies, such as multiple workstations attempting to connect to a specific external IP address over a given period.
